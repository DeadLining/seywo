# Seywo Compact 完整输入与可靠处理修正（2026-11-17）

本报告接续同日身份修正，记录 `seywo-compact-segment-5` 的最终冻结验证。完成源码修正、真实模型评测、隔离插件安装及 Hook 验证；本任务未安装到用户插件缓存，未提交或推送，未重算历史快照。

## 修正的数据流

```text
Hook 捕获不可变边界 → 按边界身份持久入队
  → 单 chat worker 导入安全对话
  → 原生轮次；超长轮次完整分片并附原文范围
  → 按预算合批 + 保留当前事项/焦点锚点的历史目录
  → 以本批引用枚举约束模型生成
  → 内容净状态只应用一次 + 结构动作顺序回放
  → 合并后的统一事项身份 + 人工锁
  → 全部成功后，事务发布主线、游标和轮次回执
  → 在队列锁内核查新事件并交接 worker 所有权
```

### 1. 输入预算与完整性

原先超长消息依赖关键词与首尾截短，中间没有关键词的要求可能不进入模型，整轮却被标记处理完成。空白压平也会改变输入内容。

现在由 `compact_input.py` 统一调度。普通原生轮次保持原样，超长内容沿句界或空白优先分片；必要时按字符切分。每片保留原生 turn ID、`part=[序号,总数]` 和精确来源范围。片段顺序可逐字还原安全投影后的用户消息和助手最终回答。单条请求可以容纳整个原生轮次时，不额外拆到多个调用。

角色片段上限为用户 1,200、助手 2,200 字符；每批最多 24 个输入单元、18,000 个对话字符。它们现在是分片预算，不是原生消息截断上限。超预算内容绕过调度直接进入 `request_payload()` 会被拒绝。工具、思考及进度正文仍排除。每片来源证据只覆盖模型实际看到的区间；原生轮次只提交一次。

### 2. 规则与模型的职责

旧 `NO_WORK` 正则会过滤“已完成”“可以”等短句，无法区分状态更新、同意方案与寒暄。现在安全用户/最终回答正文均交给同一次聚合抽取，由模型结合上下文判断是否改变工作。

没有增加逐轮分类或预摘要调用。纯回执可以不生成节点，但纯回执 Compact 可能使用一次聚合调用；不再承诺通过正则实现零调用。无新增可处理正文、未闭合轮次或已提交轮次仍不调用模型。

协议按独立生命周期划分事项：可独立解决的阻塞和验收项保留独立身份；同一事项的关注范围、优先次序凝练入其标题。独立阻塞不会只藏入主目标，修饰信息也不会自动各生成一节点。

### 3. 引用域与合并身份

`schema_for(payload)` 在生成阶段限定本批 turn 枚举；事项引用域由实际历史身份及最多 8 个可能新身份组成。Responses 和 Codex 两后端共用该 schema。运行时继续校验真实物化数量、前向引用、顺序、合并兼容性和锁，schema 不替代事务校验。

历史目录仍最多 12 项，先保留当前目标、关注、下一步及焦点阶段/支线锚点，再按相关性填充。开放 observation 等关注不会被类别过滤。

`compact_identity.py` 为目录、内容更新、结构锚点和当前重点统一提供合并身份解析。合并后经旧身份更新会落到保留节点，经旧身份选重点或进入支线也引用保留节点；没有合并来源记录的人工隐藏节点仍拒绝引用。独立身份不按标题相似性自动合并。

### 4. 原生轮次与结构动作

“一轮只属于一个片段”的约束无法表达同一用户消息里连续发生的进入与返回。现在相邻结构片段可以共享发生动作的边界轮次，数组顺序就是同轮动作顺序。仍必须覆盖所有输入轮次，引用全局非递减；倒序、交错、缺失或片段内重复引用继续拒绝。

内容变更在结构回放之外只应用一次。同一轮的主线 → 支线 → 返回能保留两次转换，并复用同一支线身份。

### 5. 持久边界队列与 worker 所有权

独立 Agent 以临时项目复现并交叉核验了以下问题：

| 原问题 | 最终处理 |
| --- | --- |
| 相同 transcript 路径的新边界覆盖 pending 旧边界 | 以 chat、事件、路径、fingerprint 及不可变捕获定位边界；不同边界不相互覆盖，同一 pending 投递可合并 |
| 队首非人类来源反复被 reclaim | 终结排除该记录，继续处理后续人类来源 |
| 模型运行期间新 Hook 的 sibling worker 返回 busy，新边界失去唤醒 | 持锁 worker 继续消费；最后在 inbox 锁内同时检查队列与释放 chat 锁，消除退出交接窗口 |
| 旧记录修正归属后目标 chat 未启动 | 持久重新入队后唤醒目标 worker |

后续片段失败时不发布半成品、不推进游标，重试只发布一次。DB 发布后状态文件写失败时，以 DB 进度恢复。故障注入还覆盖成功回执写入失败的整体回滚。人工标题、内容、阶段目标、位置、焦点和支线状态/结果锁继续保留。
