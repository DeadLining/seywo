# 任务流程图改造设计

## 产品定位

从用户选择的 Codex 聊天中，整理任务推进过程和关键决定的桌面工具。用户按项目查看任务，进入任务后查看从上到下的流程图，并可回看聊天原文。

## 产品结构

### 项目首页

选择项目后展示该项目的任务列表。每个任务显示名称、最近更新时间和简要状态；点击进入任务流程图。首页提供聊天记录入口。

### 聊天记录

列出当前项目可读取的 Codex 聊天。每条聊天提供“生成”或“更新”按钮：第一次点击分析整条聊天，以后点击补充新内容。显示处理进度和结果；未点击的聊天不主动分析。

历史聊天能否列出取决于本机记录和项目路径是否能够匹配。记录找不到或不属于当前项目时，应明确提示。

### 任务流程图

以从上到下的时间线展示目标、问题、方案、决定和结果。有原文依据的方案分支和决定变化也展示出来。点击节点查看详情和聊天原文；支持手动新增、修改、删除节点，以及调整任务归属。

任务由系统自动识别并直接显示。一条聊天可以对应多个任务，一个任务也可以关联多条聊天。系统判断错误时，用户可以合并或拆分任务。

## 数据处理规则

- 不把讨论中的建议误写成用户确认过的决定。
- 再次更新时避免重复节点，并保留用户手动修改和删除的结果。
- 没有依据时不编造时间顺序、因果关系或分支。先后发生不等于因果关系。
- 自动生成节点应能查看对应聊天原文；手动新增的内容注明为手动记录。
- 模型连接失败时显示原因，保留已有流程图。
- 未点击的聊天不因本功能被主动分析；需要检查并调整旧版 Hook 的自动提取路径。
- 原有功能和 UI 可以替换；已有聊天和项目数据先检查，再确定如何复用，不直接删除。
- 保留新流程实际需要的设置，例如模型连接；旧功能是否继续使用，以新流程需要为准。

## 现有基础与待验证事项

现有项目包含本地聊天读取、原文定位、模型连接和图谱展示能力，可以作为候选基础，但需要重新检查是否满足新流程。现有图谱主要表达事项关系，不能仅靠改变布局就当成可靠的任务时间线。

需要验证聊天列表和项目路径的匹配、聊天记录的时间顺序、跨聊天归类、增量处理和手动修改保护；此前后台提取报错也需要纳入端到端验证。

## 建议实施顺序

1. 打通选择一条聊天并生成一个或多个任务、节点及原文链接。
2. 实现自上而下的流程图、节点手动编辑和任务归属调整。
3. 实现同一聊天重复更新时的增量补充、去重、手动修改保护和跨聊天归类。

## 验收重点

使用包含多个任务、方案变化和明确决定的实际聊天验证：

- 只处理用户点击的聊天。
- 内容能够对应原文，任务归属和时间顺序可以检查与调整。
- 不把建议当成已确认的决定；不凭先后顺序编造因果关系。
- 多次点击不产生重复节点，手动修改和删除不被覆盖。
- 处理失败时，已有流程图保留，页面能展示可理解的错误。
