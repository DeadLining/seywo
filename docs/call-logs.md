# 模型调用日志

入口：项目记忆页「调用日志」弹窗，按项目、模型、结果筛选，每页 50 条，手动刷新，无后台轮询。

`runtime/sessiongraph/call_logs.py` 是轻量摘要的唯一写入与查询入口。抽取/判断复用 `request_audit` 的请求编号和传输、内容校验阶段；连通性测试独立记录，允许无项目的全局测试。一个实际请求一行；阶段重试生成不同请求，记录对应 chat、run、attempt 与阶段重试次数。服务响应成功不等于内容校验通过，更不表示最终成功入库，原有任务记录负责入库结果。

摘要仅保存时间、所请求/返回的模型名、去除鉴权信息/查询串的服务地址、HTTP 状态、耗时、服务给出的 Token 用量和固定错误代码。未给出的用量/耗时标为未知。无请求正文、模型输出、推理、错误正文、密钥和 Authorization；不进入知识图谱，也不调用模型生成日志。

存储为共享运行时的 `call-logs/calls.sqlite3`，默认 0600 / 0700。最近 7 天、SQLite 主文件最多 20 MiB（回滚日志仅在写事务中短暂存在）；超期记录在后续写入时清理，读取立即排除超期记录。接近容量时删除最早摘要并复用空闲页，无定时器、整库 VACUUM 或额外服务。日志锁最多等待 50 ms，日志失败不改变模型调用结果。只读查询不创建或写入日志库，不打开项目图谱，也不调模型。

永久删除 chat 通过现有按 job 级联链路清理对应摘要。原有 `request-audit` 详细证据及恢复策略保持独立，不受 7 天/20 MiB 的普通日志清理影响；升级不复制旧详细证据。关闭弹窗/刷新不触发抽取、恢复或补录。

开发只读桥也接受当前显式项目的调用日志查询，继续使用隔离的临时运行时；不会因此读取安装版全局日志。

回退：安装先前 App 备份；新增日志数据库为独立派生数据，不要求图谱迁移，旧版可忽略它。用户已授权提交并推送本轮改动。
